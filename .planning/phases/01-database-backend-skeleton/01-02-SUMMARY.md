## Decisions Made

1. **Next.js 16.2.7 resolved from `^16.0.0`.** The plan pinned `next: "^16.0.0"`; pnpm install resolved to current 16.2.7 (the latest minor). React 19.2.1 + react-dom 19.2.1 resolved similarly. Turbopack-enabled dev script (`next dev --turbopack -p 3001`) works in 16.x out of the box.
2. **Docker daemon + compose v2 plugin not installed on Claude's runner.** Per the plan's `<action>` block: "this REQUIRES Docker installed; if not available locally, document it and trust the verify step." The runner has Docker CLI 29.1.5 but no compose v2 plugin. YAML validation done via `python3 yaml.safe_load` (which parses the same way `docker compose config` does, modulo Docker-specific schema validation). Acceptance criteria for docker compose / docker build are deferred to the developer's local environment and to the verifier subagent.
3. **Reworded Pitfall #3 comment in Caddyfile to remove the literal string `handle_path`.** The plan's acceptance criterion `! grep -q "handle_path" Caddyfile` is a strict literal-string match — even the explanatory comment "Pitfall #3: handle_path STRIPS prefix" would fail it. Reworded to: "the alternative directive STRIPS the prefix; we use `handle` here." Same meaning, passes the strict check, still references Pitfall #3 by number.
4. **Committed `apps/web/next-env.d.ts`.** Next.js auto-generates this on `next build`. The file is the public TypeScript reference for `next/types`, and downstream `tsc --noEmit` runs expect it on disk. Per Next.js convention, it is committed to the repo (Next.js docs explicitly call this out: "This file should not be edited").
